# Packet 1 — Integrate the approved design system into the existing Next.js workspace without replacing real Phase 6 contracts with mocks. Convert the approved `DESIGN.md` tokens and frame-00 primitives into build-time Tailwind/theme and reusable typed components; preserve the high-density light shell, 280px desktop navigation, responsive diagnostic treatment, 48px enterprise rows, status/citation patterns, typography, and tonal elevation without shipping runtime Tailwind CDN or generated inline scripts.

Read the [Phase 8 shared contracts](../00-shared-contracts.md) and [canonical frontend contract](../../shared/frontend/stitch-nextjs-contract.md).

## Preconditions

- Phase 7 approved the brief/mapping, canonical tokens, localization decision, accepted references or fallback, and gap record.
- The existing Phase 6 Next.js workspace and real contracts are inspectable.
- `smart_rag/DESIGN.md` and frame 00 are accepted visual inputs.

## Allowed outputs

- Frontend theme/token configuration, reusable typed primitives, shell/layout components, tests, and documentation.
- Frame/token traceability and Phase 8 evidence.

## Forbidden outputs

- Replacing the existing workspace or real Phase 6 behavior with mocks.
- Copying generated HTML, demo data, inline scripts, random behavior, dead links, or client-only permissions.
- Runtime Tailwind CDN, unresolved token choices, prohibited blur, or CSP-incompatible external assets.

## Ordered actions

1. Inspect existing frontend conventions, dependencies, generated types, tests, and build commands.
2. Apply the approved palette, radius, elevation, typography, spacing, and no-blur decisions through build-time Tailwind/design tokens.
3. Recreate accepted frame-00 buttons, badges, citation chips, inputs, file drop zones, tables, focus/error states, and loading primitives as typed accessible components.
4. Implement the high-density light shell, 280px desktop navigation, responsive diagnostic treatment, 48px rows, status/citation patterns, and tonal elevation without disturbing real routes/contracts.
5. Add component, accessibility, responsive, and visual-regression coverage plus token/frame traceability.

## Acceptance checks

- Approved token values have one source of truth and no unresolved generated-frame conflict.
- Primitives are typed, accessible, reusable, CSP-compatible, and safe for hostile text.
- Desktop shell density, navigation width, row height, typography, elevation, and responsive diagnostics match accepted references.
- Existing Phase 6 real Auth/API/SSE behavior remains intact.

## Negative tests

- Fail on runtime CDN/script loading, inline event handlers, `innerHTML`, placeholder routes, external avatars, static live diagnostics, random auth, prohibited blur, and unapproved assets.
- Render hostile strings and long mixed-direction text in every primitive.
- Prove component visibility is not the server authorization boundary.

## Stop routes

- Return absent/conflicting Phase 7 token or frame decisions to Phase 7.
- Stop for an incompatible existing contract or dependency that changes security, data, cost, or acceptance semantics.

## Required evidence

Append `P08-01` proof to [`docs/development/phase-08-frontend-integration-evidence.md`](../../../../../docs/development/phase-08-frontend-integration-evidence.md): changed paths, token reconciliation, frame-00 traceability, visual/component/accessibility results, prohibited-pattern scan, preserved-contract proof, and open gaps.
